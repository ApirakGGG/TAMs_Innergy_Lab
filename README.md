# สรุปคู่มือ TAMS (Time Attendance Management System)

> สรุปจากภาพรวมสไลด์ (54 สไลด์) ของคู่มือผู้ใช้งาน เพื่อใช้เป็นข้อมูลตั้งต้นในการทำเว็บ LINE OA แยกอีกอัน
>
> **หมายเหตุ:** ภาพที่ได้รับเป็นภาพย่อ ข้อความในสไลด์ส่วนใหญ่เล็กเกินอ่าน จึงสรุปเฉพาะสิ่งที่เห็นชัด รายการที่ติดเครื่องหมาย ⚠️ คือส่วนที่ควรเปิดสไลด์ต้นฉบับเพื่อยืนยันรายละเอียดอีกครั้ง

---

## 1. ภาพรวมระบบ

TAMS คือระบบบริหารเวลาเข้า-ออกงาน (Time Attendance Management System) ประกอบด้วย 2 ส่วนหลัก

| ส่วน | ผู้ใช้ | ช่องทาง |
|---|---|---|
| Back End (ระบบจัดการข้อมูล) | ผู้ดูแลระบบ / HR | เว็บ `tams.works/login` |
| LINE OA @Tams | พนักงาน | LINE Official Account |

### ฟีเจอร์เด่นที่ปรากฏในสไลด์แนะนำ
- เช็คอิน/เช็คเอาท์ผ่าน **Beacon**, **WiFi** และ **GPS**
- จัดการวันลาด้วยตนเอง
- ตรวจสอบประวัติการเข้างาน
- ตรวจสอบวันหยุดบริษัท
- ระบบแจ้งเตือนสำหรับหัวหน้างาน
- จุดขายในสไลด์: ใช้งานง่าย (Easy to use), ทำงานได้ทุกที่ทุกเวลา (Work anytime), เหมาะกับผู้ใช้ (Perfect for you) ⚠️ ข้อความภาษาไทยในสไลด์ 44 ต้องตรวจซ้ำ

## 2. ระบบหลังบ้าน (Back End) — บริบทเพื่อเชื่อมกับเว็บ LINE OA

เมนูหลักในระบบหลังบ้าน:

1. Dashboard
2. Company
3. Devices
4. Employee
5. Attendance
6. Health
7. Calendar
8. Report
9. Log out

**ขั้นตอนเข้าสู่ระบบ (สไลด์ 15-16)**
1. เข้า `https://www.tams.works/login`
2. กรอก Username และ Password แล้วกด Sign In

ข้อมูลที่ตั้งค่าในหลังบ้านจะเป็นแหล่งข้อมูลให้ฝั่ง LINE OA เช่น รายชื่อพนักงาน (Employee code), ตำแหน่งสถานที่/จุดเช็คอิน (Beacon, GPS), ประเภทการลา, วันหยุดบริษัท ⚠️ ควรยืนยันว่าเมนูใดในหลังบ้านผูกกับฟีเจอร์ใดใน LINE OA

## 3. การใช้งานผ่าน LINE OA (สไลด์ 43-53) — หัวใจของงานเว็บ

### 3.1 เริ่มต้นใช้งาน

**ขั้นที่ 1 — เพิ่มเพื่อน (สไลด์ 45)**
- เพิ่ม LINE OA ชื่อ **TAMS** ด้วยการสแกน QR code หรือผ่านลิงก์เชิญเพิ่มเพื่อน
- ⚠️ ลิงก์/Account ID ในสไลด์เล็กเกินอ่าน ต้องดูจากต้นฉบับ

**ขั้นที่ 2 — ผูกบัญชีพนักงาน (สไลด์ 46)**
- พนักงานพิมพ์ **Employee code** ในแชท LINE OA Tams เพื่อลงทะเบียน/ยืนยันตัวตน
- ⚠️ ควรยืนยันข้อความตอบกลับของระบบหลังกรอกรหัส และกรณีรหัสไม่ถูกต้อง

### 3.2 ฟังก์ชันหลักของพนักงาน

| # | ฟังก์ชัน | สไลด์ | สิ่งที่เห็นในภาพ |
|---|---|---|---|
| 1 | Check In / Check Out ด้วย **Beacon** | 47 | หน้าจอมือถือแสดงการเช็คอินเมื่ออยู่ในระยะ Beacon |
| 2 | Check In / Check Out ด้วย **GPS** | 48 | เลือกตำแหน่ง แล้วกดเช็คอิน/เช็คเอาท์ มีหน้าจอยืนยัน |
| 3 | **Leave** (ขอลา) | 49 | เลือกวันที่จากปฏิทิน เลือกประเภทลา ส่งคำขอ |
| 4 | Leave — ผลลัพธ์/สถานะ | 50 | หน้าจอหลายสถานะ (เช่น ส่งสำเร็จ รออนุมัติ) ⚠️ ต้องยืนยัน |
| 5 | **Check Leave** (เช็คการลา) | 51 | ดูรายการ/สถานะการลาของตนเอง |
| 6 | **Check Holiday** (เช็ควันหยุด) | 52 | ดูรายการวันหยุดของบริษัท |
| 7 | **Check point** | 53 | ดูข้อมูลจุดเช็คอิน/ประวัติ ⚠️ ความหมายที่แน่ชัดต้องดูต้นฉบับ |

### 3.3 Flow ผู้ใช้ (ร่างจากสิ่งที่เห็น)

```
เพิ่มเพื่อน LINE OA (สแกน QR)
        ↓
กรอก Employee code → ผูกบัญชี
        ↓
เมนูหลัก
 ├─ เช็คอิน/เช็คเอาท์ (Beacon / GPS)
 ├─ ขอลา (Leave) → เลือกวัน/ประเภท → ส่ง
 ├─ เช็คการลา (Check Leave)
 ├─ เช็ควันหยุด (Check Holiday)
 └─ Check point
```

## 4. ข้อเสนอแนะสำหรับการทำเว็บ LINE OA

- หน้าเว็บส่วนใหญ่น่าจะเป็น **LIFF** (LINE Front-end Framework) เปิดในแชท LINE ออกแบบแบบ mobile-first
- ต้องมีระบบ **ผูกบัญชีด้วย Employee code** เป็นขั้นแรก
- หน้าจอที่ต้องมี: เช็คอิน/เช็คเอาท์, ขอลา, ประวัติการลา, วันหยุด, Check point
- เช็คอินด้วย GPS ต้องขอสิทธิ์ตำแหน่ง ส่วน Beacon ต้องดูว่าเว็บบน LINE รองรับหรือไม่ (Web Bluetooth มีข้อจำกัดในบางแพลตฟอร์ม) ⚠️ ควรตรวจสอบกับทีมพัฒนาเดิมว่าใช้เทคนิคใด
- ข้อมูลหลักควรเชื่อมกับ API/ฐานข้อมูลเดียวกับระบบหลังบ้าน `tams.works`

## 5. สิ่งที่ควรยืนยันจากสไลด์ต้นฉบับ

- [ ] ลิงก์/ID ของ LINE OA และ QR code (สไลด์ 45)
- [ ] ข้อความและเงื่อนไขของ Check In/Out แต่ละแบบ รวมถึงระยะ Beacon และรัศมี GPS (สไลด์ 47-48)
- [ ] ประเภทการลาที่รองรับ และขั้นตอนอนุมัติ (สไลด์ 49-51)
- [ ] ความหมายของ "Check point" (สไลด์ 53)
- [ ] ข้อมูลติดต่อในสไลด์สุดท้าย (สไลด์ 54)
- [ ] ฟังก์ชัน WiFi ที่ระบุในสไลด์แนะนำ ว่ามีใน LINE OA ด้วยหรือไม่
